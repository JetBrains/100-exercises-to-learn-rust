## `impl Trait`

`TicketStore::to_dos` повертає `Vec<&Ticket>`.\
Через таку сигнатуру кожен виклик `to_dos` призводить до нової heap allocation (виділення пам'яті в купі), а вона може бути зайвою — залежно
від того, що код, який викликає метод, робитиме з результатом.
Було б краще, якби `to_dos` повертав ітератор замість `Vec`: тоді код, що викликає метод, міг би сам вирішити,
чи збирати результати у `Vec`, чи просто перебрати їх.

Але тут є підступ!
Який тип повертає `to_dos` у наведеній нижче реалізації?

```rust
impl TicketStore {
    pub fn to_dos(&self) -> ??? {
        self.tickets.iter().filter(|t| t.status == Status::ToDo)
    }
}
```

## Типи, які не можна назвати

Метод `filter` повертає екземпляр `std::iter::Filter`, який визначено так:

```rust
pub struct Filter<I, P> { /* fields omitted */ }
```

де `I` — тип ітератора, елементи якого фільтруються, а `P` — предикат, за яким відбираються елементи.\
Ми знаємо, що в цьому випадку `I` — це `std::slice::Iter<'_, Ticket>`, а як щодо `P`?\
`P` — це closure (замикання), тобто **анонімна функція**. Як випливає з назви, closures не мають імені,
тож ми не можемо записати їхній тип у своєму коді.

У Rust для цього є рішення: **impl Trait**.

## `impl Trait`

`impl Trait` — це можливість мови, яка дає змогу повернути тип, не вказуючи його назви.
Ви лише оголошуєте, які traits реалізує цей тип (trait — набір методів, які тип може реалізувати; аналог інтерфейсу), а решту Rust з'ясує сам.

У нашому випадку ми хочемо повернути ітератор, що видає references на `Ticket`:

```rust
impl TicketStore {
    pub fn to_dos(&self) -> impl Iterator<Item = &Ticket> {
        self.tickets.iter().filter(|t| t.status == Status::ToDo)
    }
}
```

От і все!

## Generic parameter?

`impl Trait` у позиції типу повернення — це **не** generic parameter (узагальнений параметр).

Generics — це placeholders для типів, які підставляє той, хто викликає функцію.
Функція з generic parameter **поліморфна**: її можна викликати з різними типами, і компілятор згенерує
окрему реалізацію для кожного з них.

З `impl Trait` усе інакше.
Тип повернення функції з `impl Trait` **фіксується** під час компіляції, і компілятор згенерує
для неї одну-єдину реалізацію.
Саме тому `impl Trait` ще називають **opaque return type** (непрозорий тип повернення): той, хто викликає функцію, не знає точного типу значення, що повертається,
а знає лише, що цей тип реалізує вказані traits. Проте компілятор точний тип знає, тож жодного поліморфізму тут немає.

## RPIT

Читаючи RFC чи поглиблені статті про Rust, ви можете натрапити на абревіатуру **RPIT**.\
Вона розшифровується як **«Return Position Impl Trait»** (impl Trait у позиції типу повернення) і означає використання `impl Trait` як типу повернення.
