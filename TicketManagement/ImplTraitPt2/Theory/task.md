## `impl Trait` у позиції аргументу

У попередньому уроці ми бачили, як за допомогою `impl Trait` можна повернути тип, не вказуючи його назви.\
Той самий синтаксис можна використовувати і в **позиції аргументу**:

```rust
fn print_iter(iter: impl Iterator<Item = i32>) {
    for i in iter {
        println!("{}", i);
    }
}
```

`print_iter` приймає ітератор значень `i32` і виводить кожен елемент.\
У **позиції аргументу** `impl Trait` рівнозначний generic parameter з trait bound (вимогою, щоб тип реалізовував певний trait):

```rust
fn print_iter<T>(iter: T) 
where
    T: Iterator<Item = i32>
{
    for i in iter {
        println!("{}", i);
    }
}
```

## Недоліки

Загальне правило: у позиції аргументу віддавайте перевагу generics, а не `impl Trait`.\
Generics дають змогу тому, хто викликає функцію, явно вказати тип аргументу за допомогою синтаксису turbofish (`::<>`),
що буває корисно для усунення неоднозначності. З `impl Trait` так зробити не можна.
