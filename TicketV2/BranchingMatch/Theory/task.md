## `match`

Можливо, вам цікаво: а що, власне, можна **робити** з enum?\
Найпоширеніша операція — **зіставлення** (match) його з patterns (зразками).

```rust
enum Status {
    ToDo,
    InProgress,
    Done
}

impl Status {
    fn is_done(&self) -> bool {
        match self {
            Status::Done => true,
            // Оператор `|` дає змогу зіставити значення з кількома patterns.
            // Читається як «або `Status::ToDo`, або `Status::InProgress`».
            Status::InProgress | Status::ToDo => false
        }
    }
}
```

Конструкція `match` дає змогу порівняти значення Rust із низкою **patterns**.\
Її можна уявляти як `if` на рівні типів. Якщо `status` — це варіант `Done`, виконується перший блок;
якщо це варіант `InProgress` або `ToDo` — другий.

## Вичерпність

Тут є одна важлива деталь: `match` **вичерпний** (exhaustive). Ви мусите обробити всі варіанти enum.\
Якщо ви забудете обробити якийсь варіант, Rust зупинить вас помилкою ще **під час компіляції**.

Наприклад, якщо ми забудемо обробити варіант `ToDo`:

```rust
match self {
    Status::Done => true,
    Status::InProgress => false,
}
```

компілятор поскаржиться:

```text
error[E0004]: non-exhaustive patterns: `ToDo` not covered
 --> src/main.rs:5:9
  |
5 |     match status {
  |     ^^^^^^^^^^^^ pattern `ToDo` not covered
```

Це дуже важливо!\
Кодові бази з часом змінюються: згодом ви можете додати новий статус, наприклад `Blocked`. Компілятор Rust
видасть помилку для кожної конструкції `match`, у якій бракує логіки для нового варіанта.
Саме тому розробники на Rust так часто вихваляють «рефакторинг, керований компілятором» (compiler-driven refactoring):
компілятор підказує, що робити далі, а вам лишається тільки виправити те, про що він повідомляє.

## Catch-all

Якщо вам байдуже до одного чи кількох варіантів, можна використати pattern `_` як catch-all (pattern, що перехоплює все інше):

```rust
match status {
    Status::Done => true,
    _ => false
}
```

Pattern `_` відповідає будь-якому значенню, яке не збіглося з жодним із попередніх patterns.

<div class="warning">
Використовуючи такий catch-all pattern, ви _не_ отримаєте переваг рефакторингу, керованого компілятором.\
Якщо ви додасте новий варіант enum, компілятор _не_ підкаже, що ви його не обробляєте.

Якщо для вас важлива коректність, уникайте catch-all patterns. Покладіться на компілятор: нехай він допоможе переглянути всі місця зіставлення й вирішити, як обробляти нові варіанти enum.

</div>
