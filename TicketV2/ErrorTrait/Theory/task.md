## Error trait

### Звітування про помилки

У попередній вправі вам довелося деструктуризувати варіант `TitleError`, щоб дістати повідомлення про помилку й
передати його макросу `panic!`.\
Це (примітивний) приклад **звітування про помилки** (error reporting): перетворення типу помилки на представлення, яке можна
показати користувачеві, операторові сервісу чи розробникові.

Було б непрактично, якби кожен розробник на Rust вигадував власну стратегію звітування про помилки: це було б марнуванням часу,
до того ж такі рішення з різних проєктів погано поєднувалися б між собою.
Тому Rust надає trait `std::error::Error` (trait — набір методів, які тип може реалізувати; аналог інтерфейсу).

### Trait `Error`

На тип варіанта `Err` у `Result` немає жодних обмежень, але доброю практикою вважається використовувати тип,
який реалізує trait `Error`.
`Error` — наріжний камінь обробки помилок у Rust:

```rust
// Трохи спрощене визначення trait `Error`
pub trait Error: Debug + Display {}
```

Можливо, ви пам'ятаєте синтаксис `:` з уроку про [trait `From`](../../../Traits/FromTrait/Theory/task.md#supertrait--subtrait): так задають **supertraits** (traits, реалізація яких потрібна для іншого trait).
У `Error` два supertraits: `Debug` і `Display`. Якщо тип хоче реалізувати `Error`, він також має
реалізувати `Debug` і `Display`.

### `Display` і `Debug`

Ми вже зустрічали trait `Debug` в [одному з попередніх уроків](../../../Traits/DeriveMacros/Theory/task.md): саме його використовує
`assert_eq!`, щоб показати значення порівнюваних змінних, коли assertion (перевірка) не проходить.

З «механічного» погляду `Display` і `Debug` однакові: вони визначають, як тип перетворюється
на рядкове представлення:

```rust
// `Debug`
pub trait Debug {
    fn fmt(&self, f: &mut Formatter<'_>) -> Result<(), Error>;
}

// `Display`
pub trait Display {
    fn fmt(&self, f: &mut Formatter<'_>) -> Result<(), Error>;
}
```

Різниця в їхньому _призначенні_: `Display` повертає представлення, розраховане на «кінцевих користувачів»,
а `Debug` дає низькорівневе представлення, яке більше підходить розробникам та операторам сервісів.\
Саме тому `Debug` можна реалізувати автоматично за допомогою атрибута `#[derive(Debug)]`, тоді як `Display`
**потребує** ручної реалізації.
