## Деструктори

Розповідаючи про heap, ми згадували, що ви відповідаєте за звільнення пам'яті, яку виділяєте.\
Розповідаючи про borrow checker, ми також стверджували, що в Rust вам рідко доводиться керувати пам'яттю безпосередньо.

На перший погляд ці два твердження можуть здатися суперечливими.
Подивімося, як вони узгоджуються між собою, познайомившись зі **scopes** і **деструкторами**.

## Scopes

**Scope** змінної — це ділянка коду на Rust, у якій ця змінна дійсна, або **жива**.

Scope змінної починається з її оголошення.
Він закінчується, коли стається одне з двох:

1. закінчується блок (тобто код між `{}`), у якому змінну оголошено
   ```rust
   fn main() {
      // тут `x` ще поза scope
      let y = "Hello".to_string();
      let x = "World".to_string(); // <-- тут починається scope x...
      let h = "!".to_string(); //   |
   } //  <-------------- ...і тут закінчується
   ```
2. ownership змінної передається комусь іншому (наприклад, функції чи іншій змінній)
   ```rust
   fn compute(t: String) {
      // Робимо щось [...]
   }

   fn main() {
       let s = "Hello".to_string(); // <-- тут починається scope s...
                   //                    | 
       compute(s); // <------------------- ...і тут закінчується,
                   //   бо `s` переміщено в `compute`
   }
   ```

## Деструктори

Коли owner значення виходить за межі scope, Rust викликає **деструктор** цього значення.\
Деструктор намагається прибрати ресурси, які використовувало значення, — зокрема звільнити всю пам'ять, яку воно виділило.

Деструктор значення можна викликати вручну, передавши значення в `std::mem::drop`.\
Тому ви часто чутимете, як розробники на Rust кажуть, що значення «**знищено**» (dropped), маючи на увазі, що воно
вийшло за межі scope і його деструктор було викликано.

### Унаочнюємо точки drop

Ми можемо вставити явні виклики `drop`, щоб «розписати» те, що компілятор робить за нас. Повернімося до попереднього прикладу:

```rust
fn main() {
   let y = "Hello".to_string();
   let x = "World".to_string();
   let h = "!".to_string();
}
```

Він еквівалентний такому коду:

```rust
fn main() {
   let y = "Hello".to_string();
   let x = "World".to_string();
   let h = "!".to_string();
   // Змінні знищуються в порядку, зворотному до порядку їх оголошення
   drop(h);
   drop(x);
   drop(y);
}
```

Тепер розгляньмо другий приклад, де ownership `s` передається в `compute`:

```rust
fn compute(s: String) {
   // Робимо щось [...]
}

fn main() {
   let s = "Hello".to_string();
   compute(s);
}
```

Він еквівалентний такому коду:

```rust
fn compute(t: String) {
    // Робимо щось [...]
    drop(t); // <-- Якщо `t` не було знищено чи переміщено
             //     раніше, компілятор викличе
             //     `drop` тут, коли `t` вийде за межі scope
}

fn main() {
    let s = "Hello".to_string();
    compute(s);
}
```

Зверніть увагу на різницю: хоча після виклику `compute` у `main` змінна `s` уже недійсна, `drop(s)`
у `main` немає.
Передаючи функції ownership значення, ви також **передаєте їй відповідальність за його прибирання**.

Це гарантує, що деструктор значення буде викликано **щонайбільше один раз**, тож
[помилки double free](https://owasp.org/www-community/vulnerabilities/Doubly_freeing_memory) неможливі за самою побудовою мови.

> 💡 **Примітка**
>
> Rust не гарантує, що деструктори буде виконано. Наприклад, вони не виконаються, якщо
> ви свідомо вирішите [допустити витік пам'яті](../../../Threads/LeakingMemory/Theory/task.md) (memory leak).

### Використання після drop

Що станеться, якщо спробувати використати значення після того, як його знищено?

```rust
let x = "Hello".to_string();
drop(x);
println!("{}", x);
```

Якщо спробувати скомпілювати цей код, ви отримаєте помилку:

```rust
error[E0382]: use of moved value: `x`
 --> src/main.rs:4:20
  |
3 |     drop(x);
  |          - value moved here
4 |     println!("{}", x);
  |                    ^ value used here after move
```

Виклик drop **поглинає** значення, до якого його застосовано, тобто після виклику це значення стає недійсним.\
Тож компілятор не дасть вам ним скористатися, запобігаючи [помилкам use-after-free](https://owasp.org/www-community/vulnerabilities/Using_freed_memory) (використання пам'яті після її звільнення).

### Знищуємо references

А якщо змінна містить reference?\
Наприклад:

```rust
let x = 42i32;
let y = &x;
drop(y);
```

Коли ви викликаєте `drop(y)`... нічого не відбувається.\
Якщо ж справді спробувати скомпілювати цей код, ви отримаєте попередження:

```text
warning: calls to `std::mem::drop` with a reference 
         instead of an owned value does nothing
 --> src/main.rs:4:5
  |
4 |     drop(y);
  |     ^^^^^-^
  |          |
  |          argument has type `&i32`
  |
```

Це повертає нас до сказаного раніше: деструктор потрібно викликати лише один раз.\
На одне значення може бути кілька references — якби ми викликали деструктор значення, на яке вони вказують,
щойно один із них вийде за межі scope, що сталося б з рештою?
Вони вказували б на місце в пам'яті, яке вже недійсне: це так званий [**dangling pointer**](https://en.wikipedia.org/wiki/Dangling_pointer),
близький родич [**помилок use-after-free**](https://owasp.org/www-community/vulnerabilities/Using_freed_memory).
Система ownership у Rust за самою своєю побудовою виключає такі помилки.
