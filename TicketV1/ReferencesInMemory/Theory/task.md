## References

А як щодо references, наприклад `&String` чи `&mut String`? Як вони представлені в пам'яті?

Більшість references у Rust представлені в пам'яті як pointer на певне місце в пам'яті.\
Звідси випливає, що їхній розмір дорівнює розміру pointer, тобто `usize`.

Перевірити це можна за допомогою `std::mem::size_of`:

```rust
assert_eq!(std::mem::size_of::<&String>(), 8);
assert_eq!(std::mem::size_of::<&mut String>(), 8);
```

Зокрема, `&String` — це pointer на місце в пам'яті, де зберігаються метадані `String`.\
Якщо виконати такий фрагмент коду:

```rust
let s = String::from("Hey");
let r = &s;
```

у пам'яті ви отримаєте приблизно таку картину:

```
           --------------------------------------
           |                                    |
      +----v----+--------+----------+      +----|----+
Stack | pointer | length | capacity |      | pointer |
      |  |      |   3    |    5     |      |         |
      +--|  ----+--------+----------+      +---------+
         |          s                           r
         |
         v
       +---+---+---+---+---+
Heap   | H | e | y | ? | ? |
       +---+---+---+---+---+
```

Це, так би мовити, pointer на pointer на дані в heap.
Те саме стосується `&mut String`.

## Не всі pointers вказують на heap

Приклад вище має прояснити одну річ: не всі pointers вказують на heap.\
Вони просто вказують на місце в пам'яті, яке _може_ бути в heap, але не обов'язково.

> 💡 **Примітка**
>
> [Далі в курсі](../../../Traits/StringSlices/Theory/task.md) ми поговоримо про **fat pointers** («товсті» вказівники),
> тобто pointers з додатковими метаданими. Як випливає з назви, вони більші за
> pointers, які ми розглядали в цьому розділі, — їх також називають **thin pointers** («тонкі» вказівники).
