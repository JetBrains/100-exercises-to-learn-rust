## Interior mutability

Поміркуймо трохи над сигнатурою методу `send` типу `Sender`:

```rust
impl<T> Sender<T> {
    pub fn send(&self, t: T) -> Result<(), SendError<T>> {
        // [...]
    }
}
```

`send` приймає як аргумент `&self`.\
Але цей метод явно щось змінює: він додає нове повідомлення в канал.
Ще цікавіше те, що `Sender` можна клонувати: у нас може бути кілька екземплярів `Sender`,
які намагаються змінити стан каналу **одночасно**, з різних потоків.

Саме на цій ключовій властивості ми будуємо нашу клієнт-серверну архітектуру. Але чому це працює?
Хіба це не порушує правил borrowing у Rust? Як ми змінюємо дані через _immutable_ reference (незмінюване посилання)?

## Shared, а не immutable references

Коли ми знайомили вас із borrow checker (механізмом перевірки запозичень), ми назвали два типи references, які бувають у Rust:

- immutable references (`&T`)
- mutable references (`&mut T`)

Точніше було б назвати їх так:

- shared references (`&T`)
- exclusive references (`&mut T`)

Поділ на immutable та mutable — це ментальна модель, яка працює в переважній більшості випадків і чудово підходить
для знайомства з Rust. Але, як ви щойно побачили, це ще не все: `&T` насправді не гарантує, що дані, на які
він вказує, є immutable.\
Утім, не хвилюйтеся: Rust і далі дотримується своїх обіцянок.
Просто терміни мають трохи більше нюансів, ніж може здатися на перший погляд.

## `UnsafeCell`

Щоразу, коли тип дає змогу змінювати дані через shared reference, ви маєте справу з **interior mutability**.

За замовчуванням компілятор Rust припускає, що shared references є immutable. Спираючись на це припущення, він **оптимізує ваш код**.\
Компілятор може переставляти операції, кешувати значення й творити всіляку магію, щоб ваш код працював швидше.

Щоб сказати компілятору «Ні, цей shared reference насправді mutable», обгорніть дані в `UnsafeCell`.\
Щоразу, коли ви бачите тип, що підтримує interior mutability, можете бути певні: тут задіяно `UnsafeCell` —
прямо чи опосередковано.\
За допомогою `UnsafeCell`, raw pointers і `unsafe`-коду можна змінювати дані через shared references.

Але розставмо всі крапки над «і»: `UnsafeCell` — не чарівна паличка, яка дає змогу ігнорувати borrow checker!\
На `unsafe`-код і далі поширюються правила Rust щодо borrowing та псевдонімів (aliasing).
Це (просунутий) інструмент, за допомогою якого можна будувати **безпечні абстракції**, чию безпечність неможливо безпосередньо виразити
в системі типів Rust. Щоразу, коли ви використовуєте ключове слово `unsafe`, ви кажете компілятору:
«Я знаю, що роблю, я не порушу твоїх інваріантів, повір мені».

До кожної `unsafe`-функції, яку ви викликаєте, є документація з описом її **передумов безпечності** (safety preconditions):
за яких обставин її `unsafe`-блок безпечно виконувати. Передумови для `UnsafeCell` можна знайти
[у документації `std`](https://doc.rust-lang.org/std/cell/struct.UnsafeCell.html).

У цьому курсі ми не використовуватимемо `UnsafeCell` напряму й не писатимемо `unsafe`-код.
Але важливо знати, що він існує, навіщо він потрібен і як пов'язаний із типами, якими ви щодня
користуєтеся в Rust.

## Ключові приклади

Розгляньмо кілька важливих типів зі `std`, які використовують interior mutability.\
Ці типи доволі часто трапляються в коді на Rust, особливо якщо зазирнути під капот
деяких бібліотек, якими ви користуєтеся.

### Reference counting

`Rc` — це reference-counted pointer (вказівник із підрахунком посилань).\
Він обгортає значення й відстежує, скільки references на це значення існує.
Коли останній reference знищується, пам'ять, яку займає значення, звільняється.\
Значення, обгорнуте в `Rc`, є immutable: ви можете отримати на нього лише shared references.

```rust
use std::rc::Rc;

let a: Rc<String> = Rc::new("My string".to_string());
// Існує лише один reference на дані рядка.
assert_eq!(Rc::strong_count(&a), 1);

// Коли ми викликаємо `clone`, дані рядка не копіюються!
// Натомість збільшується reference count `Rc`.
let b = Rc::clone(&a);
assert_eq!(Rc::strong_count(&a), 2);
assert_eq!(Rc::strong_count(&b), 2);
// ^ І `a`, і `b` вказують на ті самі дані рядка
//   та мають спільний reference count.
```

`Rc` використовує всередині `UnsafeCell`, щоб shared references могли збільшувати й зменшувати reference count.

### `RefCell`

`RefCell` — один із найпоширеніших прикладів interior mutability в Rust.
Він дає змогу змінювати значення, обгорнуте в `RefCell`, навіть якщо у вас є лише
immutable reference на сам `RefCell`.

Це досягається завдяки **runtime borrow checking** (перевірці запозичень під час виконання).
`RefCell` під час виконання відстежує кількість (і тип) references на значення, яке він містить.
Якщо спробувати позичити значення як mutable, поки воно вже позичене як immutable,
програма запанікує — так правила borrowing у Rust завжди залишаються в силі.

```rust
use std::cell::RefCell;

let x = RefCell::new(42);

let y = x.borrow(); // Immutable borrow
let z = x.borrow_mut(); // Паніка! Уже є активний immutable borrow.
```
