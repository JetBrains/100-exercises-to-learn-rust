## Trait `Drop`

Коли ми знайомилися з [деструкторами](../../../TicketV1/Destructors/Theory/task.md),
то згадували, що функція `drop`:

1. звільняє пам'ять, яку займає тип (тобто `std::mem::size_of` байтів);
2. прибирає всі додаткові ресурси, якими може керувати значення (наприклад, буфер `String` у heap; heap: купа — динамічна пам'ять).

Саме на кроці 2 у гру вступає trait `Drop` (trait: набір методів, які тип може реалізувати; аналог інтерфейсу).

```rust
pub trait Drop {
    fn drop(&mut self);
}
```

Trait `Drop` — це механізм, за допомогою якого ви можете визначити для своїх типів _додаткову_ логіку очищення,
понад те, що компілятор робить за вас автоматично.\
Усе, що ви напишете в методі `drop`, буде виконано, коли значення вийде за межі scope.

## `Drop` і `Copy`

Говорячи про trait `Copy`, ми зазначали, що тип не може реалізувати `Copy`, якщо він
керує додатковими ресурсами, окрім тих `std::mem::size_of` байтів, які займає в пам'яті.

Можливо, ви запитаєте: звідки компілятор знає, чи керує тип додатковими ресурсами?
Ви вгадали: з реалізацій trait `Drop`!\
Якщо ваш тип має явну реалізацію `Drop`, компілятор вважатиме,
що з вашим типом пов'язані додаткові ресурси, і не дозволить вам реалізувати `Copy`.

```rust
// Це unit struct, тобто struct (структура) без полів.
#[derive(Clone, Copy)]
struct MyType;

impl Drop for MyType {
    fn drop(&mut self) {
       // Тут нічого не потрібно робити,
       // достатньо мати «порожню» реалізацію Drop
    }
}
```

Компілятор видасть ось таке повідомлення про помилку:

```text
error[E0184]: the trait `Copy` cannot be implemented for this type; 
              the type has a destructor
 --> src/lib.rs:2:17
  |
2 | #[derive(Clone, Copy)]
  |                 ^^^^ `Copy` not allowed on types with destructors
```
