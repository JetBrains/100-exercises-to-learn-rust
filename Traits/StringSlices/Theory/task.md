## Рядкові зрізи

Упродовж попередніх розділів ви бачили в коді чимало **рядкових літералів**,
як-от `"To-Do"` чи `"A ticket description"`.
За ними завжди йшов виклик `.to_string()` або `.into()`. Час зрозуміти чому!

## Рядкові літерали

Щоб визначити рядковий літерал, потрібний текст беруть у подвійні лапки:

```rust
let s = "Hello, world!";
```

Тип `s` — `&str`, тобто **посилання на рядковий зріз**.

## Розміщення в пам'яті

`&str` і `String` — різні типи, вони не взаємозамінні.\
Пригадаймо з нашого [попереднього дослідження](../../../TicketV1/Heap/Theory/task.md),
як `String` розміщується в пам'яті.
Якщо виконати:

```rust
let mut s = String::with_capacity(5);
s.push_str("Hello");
```

то в пам'яті отримаємо таку картину:

```text
      +---------+--------+----------+
Stack | pointer | length | capacity | 
      |  |      |   5    |    5     |
      +--|------+--------+----------+
         |
         |
         v
       +---+---+---+---+---+
Heap:  | H | e | l | l | o |
       +---+---+---+---+---+
```

Якщо пам'ятаєте, ми [також розглядали](../../../TicketV1/ReferencesInMemory/Theory/task.md),
як `&String` розміщується в пам'яті:

```text
     --------------------------------------
     |                                    |         
+----v----+--------+----------+      +----|----+
| pointer | length | capacity |      | pointer |
|    |    |   5    |    5     |      |         |
+----|----+--------+----------+      +---------+
     |        s                          &s 
     |       
     v       
   +---+---+---+---+---+
   | H | e | l | l | o |
   +---+---+---+---+---+
```

`&String` вказує на ділянку пам'яті, де зберігаються метадані `String`.\
Якщо перейти за вказівником, ми потрапимо до даних, розміщених у купі. Зокрема, до першого байта рядка — `H`.

А що, як нам потрібен тип, який представляє **підрядок** `s`? Наприклад, `ello` у `Hello`?

## Рядкові зрізи

`&str` — це **представлення** (view) рядка, **посилання** на послідовність байтів UTF-8, що зберігається деінде.
Наприклад, `&str` можна створити зі `String` ось так:

```rust
let mut s = String::with_capacity(5);
s.push_str("Hello");
// Створюємо посилання на рядковий зріз зі `String`,
// пропускаючи перший байт.
let slice: &str = &s[1..];
```

У пам'яті це виглядатиме так:

```text
                    s                              slice
      +---------+--------+----------+      +---------+--------+
Stack | pointer | length | capacity |      | pointer | length |
      |    |    |   5    |    5     |      |    |    |   4    |
      +----|----+--------+----------+      +----|----+--------+
           |        s                           |  
           |                                    |
           v                                    | 
         +---+---+---+---+---+                  |
Heap:    | H | e | l | l | o |                  |
         +---+---+---+---+---+                  |
               ^                                |
               |                                |
               +--------------------------------+
```

`slice` зберігає в стеку два значення:

- Вказівник на перший байт зрізу.
- Довжину зрізу.

`slice` не володіє даними, а лише вказує на них: це **посилання** на дані `String`, розміщені в купі.\
Коли `slice` знищується (drop), пам'ять у купі не звільняється, бо даними досі володіє `s`.
Саме тому `slice` не має поля `capacity`: він не володіє даними, тож йому не потрібно знати, скільки
місця під них виділено; його цікавлять лише дані, на які він посилається.

## `&str` чи `&String`

Емпіричне правило: щоразу, коли вам потрібне посилання на текстові дані, використовуйте `&str`, а не `&String`.\
`&str` гнучкіший і загалом вважається ідіоматичнішим у коді на Rust.

Якщо метод повертає `&String`, ви обіцяєте, що десь у купі є текст UTF-8, який
**точно збігається** з тим, на який ви повертаєте посилання.\
Якщо ж метод повертає `&str`, у вас значно більше свободи: ви лише стверджуєте, що _десь_ є
якісь текстові дані і що певна їх частина відповідає тому, що вам потрібно, тож ви повертаєте посилання на неї.
