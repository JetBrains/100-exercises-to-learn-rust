## Копіювання значень, ч. 1

У попередньому розділі ми познайомилися з ownership і borrowing (запозичення: тимчасовий доступ до значення без передачі ownership).\
Зокрема, ми з'ясували, що:

- У кожного значення в Rust у будь-який момент часу є лише один owner (власник значення).
- Коли функція забирає ownership значення («поглинає (consume) його»), код, що її викликав, більше не може використовувати це значення.

Ці обмеження можуть дещо заважати.\
Іноді доводиться викликати функцію, яка забирає ownership значення, але це значення
все одно потрібне нам і після виклику.

```rust
fn consumer(s: String) { /* */ }

fn example() {
     let mut s = String::from("hello");
     consumer(s);
     s.push_str(", world!"); // error: value borrowed here after move
}
```

Саме тут стане в пригоді `Clone`.

## `Clone`

`Clone` — це trait, визначений у стандартній бібліотеці Rust:

```rust
pub trait Clone {
    fn clone(&self) -> Self;
}
```

Його метод `clone` приймає reference на `self` і повертає новий екземпляр того самого типу — **owned value** (значення, яким хтось володіє).

## У дії

Повернімося до прикладу вище: за допомогою `clone` можна створити новий екземпляр `String` перед викликом `consumer`:

```rust
fn consumer(s: String) { /* */ }

fn example() {
     let mut s = String::from("hello");
     let t = s.clone();
     consumer(t);
     s.push_str(", world!"); // помилки немає
}
```

Замість того щоб передавати ownership `s` у `consumer`, ми створюємо новий `String` (клонуючи `s`) і передаємо
`consumer` саме його.\
`s` залишається дійсним і придатним до використання після виклику `consumer`.

## У пам'яті

Подивімося, що відбувалося в пам'яті в прикладі вище.
Коли виконується `let mut s = String::from("hello");`, пам'ять виглядає так:

```text
                    s
      +---------+--------+----------+
Stack | pointer | length | capacity | 
      |  |      |   5    |    5     |
      +--|------+--------+----------+
         |
         |
         v
       +---+---+---+---+---+
Heap:  | H | e | l | l | o |
       +---+---+---+---+---+
```

Коли виконується `let t = s.clone()`, у heap виділяється цілком нова ділянка пам'яті, у якій зберігається копія даних:

```text
                    s                                    t
      +---------+--------+----------+      +---------+--------+----------+
Stack | pointer | length | capacity |      | pointer | length | capacity |
      |  |      |   5    |    5     |      |  |      |   5    |    5     |
      +--|------+--------+----------+      +--|------+--------+----------+
         |                                    |
         |                                    |
         v                                    v
       +---+---+---+---+---+                +---+---+---+---+---+
Heap:  | H | e | l | l | o |                | H | e | l | l | o |
       +---+---+---+---+---+                +---+---+---+---+---+
```

Якщо ви прийшли з мови на кшталт Java, можна вважати `clone` способом створити глибоку копію об'єкта.

## Реалізація `Clone`

Щоб значення типу можна було клонувати (тобто щоб тип був `Clone`), для нього потрібно реалізувати trait `Clone`.\
Майже завжди `Clone` реалізують за допомогою derive macro (derive-макрос):

```rust
#[derive(Clone)]
struct MyType {
    // поля
}
```

Компілятор реалізує `Clone` для `MyType` саме так, як ви й очікуєте: клонує кожне поле `MyType` окремо, а
потім створює з клонованих полів новий екземпляр `MyType`.\
Пам'ятайте, що досліджувати код, який генерують `derive` macros, можна за допомогою `cargo expand` (або вашої IDE).
